# 第一课 · 5 分钟看懂这个项目（不用开 IDEA）

> 读这一篇不需要写代码、不需要开 IDE，手机躺床上也能看。
> 看完你应该能回答一个问题：**"你这个秒杀项目怎么做到不超卖的？"**

## 0. 先记住一句话

这个项目做的事：**一万个人同时抢 1000 件商品，保证只卖出去 1000 件，不多卖一件。**

面试官所有追问，都是围绕这句话展开的。

## 1. 十四个文件分别是干什么的

| 文件 | 一句话说明 | 面试可能问 |
|---|---|---|
| `SeckillApplication` | 启动类，`@SpringBootApplication` | 为什么一个 main 方法就能起 Web 服务 |
| `controller/SeckillController` | 3 个 HTTP 接口（详情 / 秒杀 / 查结果） | 为什么 skuId 用 `@PathVariable` 而 userId 用 `@RequestParam` |
| `service/SeckillService` | 接口，只声明 3 个方法 | 为什么要接口（D9 换 Redis 实现时不用改 Controller） |
| `service/impl/SeckillServiceImpl` | **真正的业务逻辑，你要写的三个方法** | 事务边界为什么在 Service 层 |
| `mapper/SkuStockMapper` | 库存表 DAO + 一条自定义 `@Update` | 为什么不用"先查再改" |
| `mapper/SeckillOrderMapper` | 订单表 DAO，只用 `BaseMapper` | MyBatis-Plus 怎么省掉 XML |
| `entity/SkuStock` / `SeckillOrder` | 两张表的字段映射 | `@TableName` `@TableId` 在干什么 |
| `common/Result` | 统一返回体 `{code,msg,data}` | 为什么不直接返回实体 |
| `common/BizException` | 带业务码的异常 | 异常 vs 返回值，怎么选 |
| `common/GlobalExceptionHandler` | 把异常翻译成 JSON | 为什么 404 不能变成 500 |
| `config/RedisConfig` | RedisTemplate + Lua 脚本加载 | 秒杀为什么用 Lua（原子性） |
| `config/RabbitConfig` | 3 个队列 + 死信队列 | 为什么用 MQ 异步落库 |
| `consumer/OrderConsumer` | 异步消费、真正落订单 | 消息重复投递怎么办（幂等） |

一句话串起来：**Controller 接活 → Service 干业务 → Mapper 碰数据库 → Result 统一出口。**

## 2. 一次秒杀请求走过哪几步

```
POST /api/seckill/1001?userId=888
  → Tomcat 分配一个 nio-8080-exec-N 线程
  → SeckillController.seckill(1001, 888)
  → SeckillServiceImpl.seckill()
      ① 扣库存：update sku_stock set stock=stock-1 ... where sku_id=1001 and stock>=1
         影响行数 1 → 扣成功；0 → 已售罄，直接返回
      ② 插订单：insert into seckill_order ...（撞 UK(user_id,sku_id) 就回滚）
      ③ 事务提交
  → 返回 {"code":0,"msg":"ok","data":"订单号"}
```

真实的启动日志长这样（`~~~` 后面是我的批注）：

```
INFO 38576 --- [seckill] [main] c.w.s.SeckillApplication : Starting SeckillApplication using Java 17.0.17
INFO 38576 --- [seckill] [main] o.s.b.w.e.tomcat.TomcatWebServer  : Tomcat started on port 8080 (http)
INFO 38576 --- [seckill] [main] o.s.a.r.c.CachingConnectionFactory: Created new connection: rabbitConnectionFactory#... localPort=7561
INFO 38576 --- [seckill] [main] c.w.s.SeckillApplication        : Started SeckillApplication in 1.871 seconds
INFO 38576 --- [seckill] [nio-8080-exec-1] com.zaxxer.hikari.HikariDataSource : HikariPool-1 - Start completed.
```

- 第 1 行：JDK 17 起来了（`发行版本` 报错就是这行不对）
- 第 2 行：8080 端口占住了（端口冲突就是这行失败）
- 第 3 行：RabbitMQ 连上了（连不上这行会重试报错）
- 第 4 行：**`Started ... in 1.871 seconds` = 启动成功**
- 第 5 行：第一次访问接口时才建数据库连接池（懒加载，正常现象）

## 3. 不超卖，就靠那一行 SQL

```sql
update sku_stock
   set stock = stock - 1, sold = sold + 1
 where sku_id = 1001 and stock >= 1
```

- **`where stock >= 1`** 是灵魂：数据库对同一行加行锁，一个事务改完别的才能改；`stock` 到 0 之后，这个条件永远不成立，影响行数就是 0。
- 用**影响行数**判断成败，而不是先 `select` 出来看一眼。

反面教材（新手常写）：

```java
int stock = mapper.selectStock();      // 两个线程都读到 1
if (stock > 0) {
    mapper.updateStock(stock - 1);     // 两个线程都扣 → 超卖
}
```

## 4. 30 秒自己验证三次（现在就做，别等明天）

```powershell
# ① 详情：剩余多少件
curl "http://127.0.0.1:8080/api/seckill/detail/1001"
# → {"code":0,"msg":"ok","data":"iPhone 16 Pro 256G（秒杀） 剩余 1000"}

# ② 抢一次（换个 userId）
curl -X POST "http://127.0.0.1:8080/api/seckill/1001?userId=888"
# → {"code":0,"msg":"ok","data":"1792931111110888"}

# ③ 同一个 userId 再抢一次 —— 这里就是"一人一单"
curl -X POST "http://127.0.0.1:8080/api/seckill/1001?userId=888"
# → {"code":1003,"msg":"你已经抢到过了，一人一单"}
```

看到这三行输出，你就已经理解了整个项目的 70%。
